# MAVEN-Pep

Reproducibility code for the MAVEN-Pep manuscript: modular C5a peptide prioritization, explicit software contracts for local planning, candidate panel selection, and reproduction of the recorded model evaluations.

The mechanism produces a researcher-defined priority score. It is not an activity probability or a calibrated biological confidence bound. The frozen expert records contain sequence representations and physicochemical properties; they do not establish peptide efficacy. Experimental feedback learning is future work.

## Reproduce the released results

Use Python 3.11 or newer from the repository root. Offline selection and model-answer re-scoring use the Python standard library and need no model, API key, GPU, or network connection.

```bash
python -B scripts/offline_selection.py
python -B scripts/offline_selection.py --validate
python -B scripts/compare_panels.py --output-dir reproduced/mechanism_panel
python -B scripts/reproduce_model_results.py --output-dir reproduced
python -B -m unittest discover -s tests -v
```

The first command returns ten candidates for the default C5a request. `--validate` checks successful selection, terminal constraints, unsupported and missing targets, insufficient candidates, incomplete construct identity, changed frozen assets, and the network connection guard. Its planner is a deterministic reference policy; this command does not run a language model.

The panel comparison regenerates all 11 recorded panels from 4,800 constructs and 1,200 amino acid sequences. The regression tests compare every released panel member and numerical column to the recorded results. The re-scoring command applies the unchanged executable contracts to all 144 saved model first answers, reconstructs the public deterministic comparator, and reproduces the paired cluster bootstrap. It also rebuilds continuation-arm aggregates from the released case scores and training records. Output goes into ignored `reproduced/`; use a fresh directory when rerunning commands that protect existing results.

| Result | Expected reproduction |

| Sequence top ten | 10 distinct sequences; mean priority 0.9226762287 |

These are results for fixed software-contract cases and development diagnostics. The three-model confirmation supplement is not the complete originally proposed eleven-model panel. Cases, recorded answers, and historical scoring gold are released here; the gold was excluded from the original inference inputs. Public rules use public input only and do not fill hidden normalized evidence fields. Zero errors accepted by an identical post-validator follows from its construction; correct-run coverage measures its usability cost.

## Figures and sensitivity analyses

```bash
python -m pip install -r requirements.txt
python -B scripts/make_figures.py --output-dir reproduced/figures
python -B scripts/check_ties.py --output reproduced/tie_sensitivity.csv
python -B scripts/check_monte_carlo.py --output-dir reproduced/monte_carlo
```

Figure data come from `results/`, the recorded manuscript tables. The command recreates the three quantitative figures as PNG and SVG. The two workflow diagrams supplied for the manuscript are illustrations and are not generated by these scripts. The Monte Carlo diagnostic uses the original seeds 0–19 and draw counts 48/96/192/384, compared with 1,536 draws from the same seed. It changes no default scoring parameter.

## Files and availability

| Location | Contents |
| --- | --- |
| `src/legacy_maven/` | Preserved mechanism, feature calculation and modular catalogue generation |
| `src/maven_final/` | Contracts, identity checks, frozen evidence checks, workflow and runtime helpers |
| `assets/` | Catalogue, sequence-only expert snapshot, target snapshot, reference projection and asset integrity manifest |
| `data/confirmation/` | 48 public cases, released historical scoring gold and 144 model first answers |
| `data/retention/` | Per-case scores for the two continuation arms, without source database records |
| `data/training/` | Synthetic domain contract rows in gzip format and fixed training slot order |
| `results/` | Recorded manuscript tables, provenance, training completion records and optimization traces |
| `scripts/` | Portable selection, re-scoring, plotting, diagnostics and optional inference entry points |
| `training/` | Portable fixed-budget continuation worker and original semantic loss helpers |

Scientific ranking source and catalogue bytes are preserved. Absolute deployment paths in metadata and frozen expert source names are replaced with portable names; sequence, embedding, property and scoring values are unchanged. `assets/asset_manifest.json` binds the public projection. The original digest is retained for assets whose metadata changed. Its integrity check detects changes to the distributed artifacts; it is not an independent timestamp or proof of the original discovery chronology.

The target projection records [UniProt P01031](https://www.uniprot.org/uniprotkb/P01031/entry). Expert source names identify ESM-2 and Biopython ProtParam. Their upstream terms continue to apply. No restricted database dump, credentials, foundation model weight, tokenizer directory or LoRA weight is distributed. The historical database-derived replay records are excluded because redistribution permission has not been established. The historical legacy-case scores can be aggregated, but their database-derived inputs and answers cannot be independently re-scored from this package. Evaluation output-token totals are recorded descriptive measurements, not regenerated inference measurements.

## Optional new model inference

This requires external Qwen3-8B weights, the historical R1 adapter/tokenizer and, for R6, the corresponding adapter. None is included. Model identity hashes are in `results/model_confirmation/model_identity.json`. Install a CUDA-compatible PyTorch build for your hardware, then `requirements-gpu.txt`. The recorded confirmation inference and both continuation arms used PyTorch `2.14.0+cu126`, CUDA 12.6, Transformers 4.57.6 and PEFT 0.18.1. The continuation records also report Python 3.10.12, NumPy 2.2.6 and a Tesla PG500-216 GPU. These values come from the released inference provenance and per-arm `environment.json` records.

```bash
python -m pip install -r requirements-gpu.txt
python -B scripts/infer_confirmation.py --model candidate --base /path/to/Qwen3-8B --old-adapter /path/to/R1 --candidate /path/to/R6 --output-dir reproduced/new_predictions
```

Use `--model base` or `--model old` for the other arms; the R1 directory also supplies the original tokenizer. The script retains greedy decoding, the 480-token generation limit, four-case batches and disabled thinking. It reads public cases only and refuses to overwrite first answers. A fresh local run records its own provenance; numerical identity across different GPU/software environments is not promised. Re-scoring the included historical answers is the independently runnable path for the manuscript numbers.

## Optional continuation training

`training/train_arm.py` preserves the original 128-update calculation: global batch 32, learning rate 2e-6 with the fixed schedule, assistant-only supervision, semantic loss weights, FP16 base and FP32 trainable LoRA. It is a portable source adaptation, not the historical worker byte sequence.

Extract a separate training-data directory with the following command. The published domain rows retain the original messages, targets, inputs and order; only 504 source-path metadata values have portable names. Arm B additionally needs the externally supplied historical `replay_rows.jsonl`. File hashes in `training/protocol.json` enforce the published domain records and original external replay file. The original domain-file digest is recorded separately. You also need the exact tokenizer, base weights and R6 parent adapter. The original R6 training corpus and upstream adapter training are not reconstructed here.

```bash
python -B scripts/prepare_training_data.py --output-dir reproduced/training_data
python -B training/train_arm.py --mode validate --arm A --data-dir /path/to/training-data --tokenizer /path/to/tokenizer --output-dir reproduced/arm_A_validation
python -B training/train_arm.py --mode train --arm A --data-dir /path/to/training-data --tokenizer /path/to/tokenizer --base-model /path/to/Qwen3-8B --parent-adapter /path/to/R6 --output-dir reproduced/arm_A_training
```

Use `--arm B` after supplying the exact replay file. The worker verifies external files before allocating the model. The public release was tested for offline numerical reproduction and CLI parsing; GPU inference and training require the missing external assets and were not rerun during packaging.
